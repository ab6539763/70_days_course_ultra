# 单日课件撰写执行手册(给撰写者/撰写Agent看的操作说明)

在动笔写任何一天的课件之前,请按顺序完成:

1. 完整阅读 `course/00-bible/00-master-bible.md`(人物、公司、产品、技术栈、仓库结构、写作红线)。
2. 完整阅读 `course/00-bible/01-beat-sheet.md` 中"当天条目",以及紧邻的前一天、后一天条目(保证首尾呼应,当天结尾要为下一天埋钩子,开头要承接上一天结尾)。
3. 对照用户提供的《零基础大模型应用开发70天培训课程详细课表》原文中对应天的技术教学点(已经在beat sheet中转述过技术主线,但如需更细节,以原课表为准),确保技术知识点覆盖完整、不遗漏原课表中提到的任何一个知识点。

## 输出要求

- 输出为一个独立的Markdown文件,路径按分配的路径写入(例如 `course/stage1-python-basics/day01_开发环境与第一行代码.md`)。
- 严格使用 `course/00-bible/00-master-bible.md` 第四章给出的模块顺序与命名撰写全文(标题元信息、旁白、晨会纪要、需求文档、架构设计图、流程图、示意图、课堂笔记、代码实战、今日复盘、课后作业、作业参考答案、明日预告)。
- 图表统一使用 Mermaid 代码块(` ```mermaid `),类型可选 `graph TD`/`flowchart TD`/`sequenceDiagram`/`classDiagram`/`stateDiagram-v2` 等,选择最贴合当天内容的图形。每天至少包含:1张架构设计图 + 1张流程图 + 1张示意图,三张图不能画成一样的内容,要分别服务于"系统结构"、"处理流程"、"概念类比"三个不同目的。
- **正文文字总量(不含代码块)不少于30000字**。这是硬性要求,写作时要靠"课堂笔记"部分的高信息密度来达成,包括:知识点讲解、真实业务场景类比、常见报错与排查过程(给出具体报错信息文本与解决步骤)、与前后知识的呼应、人物对话与互动细节、多个循序渐进的例子(不能用一个例子敷衍多个知识点)。写作时可以进行字数自检,内容显得单薄就继续补充案例、补充对比表格、补充FAQ。
- **代码要求**:所有代码块必须是完整、可读、体现企业级规范的代码(合理的模块划分、异常处理、类型注解、中文docstring与行内注释解释设计意图),严禁出现"# ...此处省略..."类占位注释来敷衍实现;如遇到确实冗长的重复性样板(如大段测试数据),可以适度精简但核心逻辑必须完整。每天课件的代码总行数目标:理论/复习/答辩类天次(参考beat sheet可判断)不少于400行,常规实操类天次不少于1200行,重大项目/集成类天次(如Day12、14、24、30、36-37、43、47-49、53、55-56、59-64)不少于2500行,力争覆盖多个完整文件而不是零散片段。
- **旁白**:至少一处清晰标注的"【旁白】"段落,以稍微跳出叙事的编者视角,解读这一天在整个70天故事和技术脉络中的位置和意义,可以点出隐藏的因果关系(例如"这一天陈铭随手写的重试装饰器,三十天后会在寰宇项目的高并发场景里救他一命")。
- **作业**:不少于5道题,覆盖概念题、代码题、思考题(结合当天的企业场景),难度递进;每题必须给出**详细的参考答案**(代码题给出完整代码,概念题给出有理有据的分析,不能只写"略"或"见课堂内容")。
- **人物一致性**:严格使用master bible中的人物姓名与角色分工,不要新造主要角色;如果情节需要一个临时小配角(例如某天需要"客户方一位工程师"),可以自然命名一个一次性角色,但不要喧宾夺主。
- **禁止痕迹**:不出现"作为AI"、"我将为您生成"等自指表述;不使用"首先...其次...最后..."这类每天雷同的机械分段套话反复出现;每天的开篇方式、旁白角度、复盘方式要有变化,避免模板感过强导致的"一眼AI"痕迹;可适当加入具体的、略带生活气的细节(比如某天下雨、某天点了外卖、某天键盘卡了一下)增强真实感,但不要喧宾夺主偏离技术主线。
- **技术准确性**:代码与技术叙述要经得起有经验的工程师检验,不能出现常识性错误;涉及API示例时使用master bible约定的模型与SDK(DeepSeek/Qwen为主,OpenAI SDK通用调用方式),环境变量命名遵循约定。
- **连续性检查**:写完后自己检查——今天的开头是否呼应了beat sheet里"前一天"的衔接点?今天的结尾"明日预告"是否呼应了beat sheet里"当天"的衔接点?人物当前的职级、项目进度是否与master bible第五章的Sprint表一致?

## 写完后自查清单(在心里过一遍,不必写进产出文件)

- [ ] 正文字数(不含代码)≥30000字
- [ ] 三类图表(架构图/流程图/示意图)齐全且内容不同质化
- [ ] 至少一处明确的【旁白】段落
- [ ] 代码完整、有详细中文注释、行数达标
- [ ] 作业≥5题且每题有详细答案
- [ ] 与前后天的衔接自然
- [ ] 人物、公司、产品、技术栈信息与bible一致
- [ ] 无AI痕迹用语
